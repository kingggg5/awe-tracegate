# AWE Agent Harness

[![CI](https://github.com/kingggg5/awe-agent-harness/actions/workflows/ci.yml/badge.svg)](https://github.com/kingggg5/awe-agent-harness/actions/workflows/ci.yml)

[![Python 3.11+](https://img.shields.io/badge/python-3.11%2B-3776AB.svg)](https://www.python.org/)

**Review repeated agent traces and compile only the workflow structure that the
evidence supports.**

> **Status: pre-alpha.** AWE is an experimental, read-only compiler and reviewer.
> It does not run agents, call models, browse the web, execute tools, or promote a
> candidate automatically. Do not use its output as authorization for a
> production action.

AWE Agent Harness accepts successful execution traces, proves a narrow set of
data dependencies, and emits either a versioned workflow candidate or an
explicit refusal. Every result binds the normalized input bundle and emitted
decision to a canonical SHA-256 receipt for offline reproduction and review.

The compiler and verifier run locally without an LLM or provider key. An agent
skill may make the CLI easier to invoke, but instructions generated by an agent
are not verification evidence; the typed receipt is the review artifact.

## What ships in this preview

- Immutable `ExecutionTrace` and compiled-workflow candidate contracts.
- An offline compiler for repeated, successful, read-only traces.
- Proven dependency edges derived from explicit `workflow_input` and
  `step_output` bindings.
- Conservative `compiled` or `refused` decisions.
- Canonical JSON receipts with an input-bundle digest, compiler version, and
  SHA-256 receipt hash.
- A small typed HTTP API for local integration.

## What does not ship

- An agent runtime, planner, model router, browser, or workflow scheduler.
- Shell execution, write tools, deployment, rollback, or autonomous remediation.
- Automatic learning, self-modification, or unattended promotion.
- A claim that a compiled workflow is globally optimal, safe for every setting,
  or novel research.

## Quickstart

Requires Python 3.11 or newer.

```bash
git clone https://github.com/kingggg5/awe-agent-harness.git
cd awe-agent-harness
python -m venv .venv
```

Activate the environment (`.venv\\Scripts\\activate` on Windows or
`source .venv/bin/activate` on macOS/Linux), then install the development and
API extras:

```bash
python -m pip install -e ".[dev,api]"
```

Compile the included repository-analysis traces:

```bash
awe compile --traces examples/repo_analysis/traces.jsonl
```

The command writes one JSON receipt to standard output and returns:

| Exit | Meaning |
| ---: | --- |
| `0` | A workflow candidate was compiled. |
| `2` | The evidence or safety policy required a refusal. |
| `1` | The input or invocation was malformed. |

The example file contains one `ExecutionTrace` per JSONL line. Compilation
requires at least two successful traces with the same ordered pure/read nodes
and explicit bindings; ambiguity or a write-like operation is refused.

Run the test suite:

```bash
python -m pytest
```

To try the optional local API:

```bash
uvicorn awe_harness.api:app --reload
```

Use `GET /healthz` for readiness and `POST /v1/compile` with a typed
`{"traces": [...]}` request. The endpoint returns the same receipt contract as
the CLI.

## How to read a result

A `compiled` result means only that the observed traces support the emitted
read-only structure under the current contract. It is a candidate for human
review and downstream evaluation, not permission to execute it.

A `refused` result is expected when evidence is insufficient, bindings conflict,
steps are not safely classifiable, or the traces contain unsupported effects.
Refusal is a product outcome, not a compiler crash.
